# YI / CSW：候補の可視性・媒介選択と「無かった」の誤認

状態：**Research protocol / Draft。合成traceの構造検査のみ実行対象。比較実験・利用者評価はNOT RUN。**  
基準：TAI main `6ba54b8423457bf543066b9780dce58296e764ef`（2026-11-05）。  
対応：[YI 64卦・変爻の探索比較（PR #269、2026-11-06統合済み）](https://github.com/hat47x/tai-pleroma/pull/269)、[RQ6：生成的探索と証拠制約](../COGNITIVE_GENERATION_AND_EVIDENCE_2026-11-02.md)、[Product Value適正化 #422](https://github.com/hat47x/tai-pleroma/issues/422)、[Draft PR #423](https://github.com/hat47x/tai-pleroma/pull/423)、[CSW Draft PR #594](https://github.com/hat47x/cultural-substrate-weaving/pull/594)。各Owner判断・既存研究正本を置換しない。

## 1. 見いだした設計上の盲点

**見つけた課題の数**で文化的体系を使った探索の価値を測ると、次の変化が見えない。

- 候補は生まれたが、記録されなかった。
- 記録されたが、その後の検索対象に入らなかった。
- 検索されたが、媒介者が提示しなかった。
- 提示されたが、評価されなかった。
- 評価されたが、推奨されなかった。
- 推奨されたが、Ownerは採用しなかった（または採否自体が未確認）。

後段の出力から前段の**候補の不存在**を推論できない。逆に、後段に未提示候補が残ることから「意図的に隠された」と断定もできない。フィルタリング、入力制約、取得失敗、記録漏れ、本人の希望などの理由を、**観測と推論**で分ける必要がある。

CSWの生成・批評・媒介は固定3-Agent実装ではない。媒介者の**提示選択効果**と、生成規則がもたらす新規性を分けて評価する。批評が誤りを指摘しても、そのことだけで作者・Product Ownerの採否、Providerの実権限は成立しない。

## 3. 「ない」の六つを区別する

この研究では、対象とした**一回の試行run**に限り以下を観測する。実在する可能性のある全候補の集合については、常に`unknown`を許す。

| 状態に関する主張 | その主張の最小条件 | 主張してはいけないこと |
| --- | --- | --- |
| このrunの生成ログに観測なし | 記録方法・生成境界・ログ取得の範囲が固定されている | 世界中・別モデル・別機会でも生成され得ない |
| 生成ログにあるが保存集合にない | 両段階の記録がrun内で閉じ、同一候補を特定できる | 不保存の理由を確認なしに推測する |
| 保存集合にあるが検索集合にない | 保存集合に到達でき、検索対象範囲が明示されている | 検索されなかった＝重要でない |
| 検索されたが提示集合にない | 検索・提示集合の境界が同じrunで閉じている | 提示されない＝否定／拒否された |
| 提示されたが評価集合にない | 提示時点と評価対象を追跡できる | 未評価＝質が悪い |
| 評価されたが推奨集合にない | 評価と推奨の境界が記録されている | 未推奨＝Ownerが棄却・正式拒否した |

これらの観測は、**すべてを記録・公開せよという要求ではない**。私的思考、非公開の資料、他者のデータ、内部推論は勝手に収集しない。許された合成ID・件数・欠落の段階・範囲・理由の確実性だけでも、比較実験の際に必要な違いを残せる。

「候補がそもそも生成されなかった」という負の主張は、生成が有限で閉じた特定runの記録に限る。生成されなかった可能性・外部での存在可能性は`unknown`として扱い、確認不能を不存在に変換しない。

## 4. 独立した比較計画への接続

[Draft #269](https://github.com/hat47x/tai-pleroma/pull/269)の探索方法A=通常レビュー、B=本卦・変爻等を併用する探索、C=文化的文章量を揃えたplacebo比較、[RQ6](../COGNITIVE_GENERATION_AND_EVIDENCE_2026-11-02.md)の生成Method×根拠検証の4条件を**新しいArm名や総合スコアで置き換えない**。

各Armの評価で、同じ入力・対象版・時間/トークン枠・利用許可のもと、以下を**補助的な観測**として事前固定する。

1. 候補ごとに生成・保存・検索・提示・評価・推奨のうち、観測した**最終段階**と各段の分母をrunの範囲で記す。未観測段階は`unknown`。
2. 生成者と媒介者を同じ主体が担った場合はそう記録する。別役割にしたときは、候補内容が独立に漏れたか、媒介者が候補の由来を知っていたかを記す。
3. 候補の評点を付ける前に**独立した評価者用のCandidate一覧**を確保する。匿名化しても区別可能な出典・条件・反証を消さず、Armのラベルは隠せる範囲で隠す。
4. 測るもの：重要な少数反証の提示到達、全候補中の評価された割合、未提示の理由の記録率、対照Armとの差、過剰な候補増加による人の確認負担。創造性の件数やモデルの自信だけで優越性を主張しない。
5. 事前に独立Oracleがない場合は、重要性や選択の公正さを**機械的PASSにしない**。評価者間の不一致を残す。原因が不明な脱落は`unknown`と記す。

**反証条件**：文化的体系の使用で候補量だけ増え、重要反証の提示到達・検証可能な新規課題・受理者の負担が改善しないなら、探索Methodとしての導入を正当化しない。「提示量を絞る」こと自体が悪なのではない。問題は、内容と失われた機会を確認できないまま、**提示結果から探索全体の網羅を主張すること**。

## 5. 最小合成traceと観測可能な失敗

[合成fixture](../fixtures/yi-selection-surface-synthetic.json)と[チェック](../check_yi_selection_surface.py)は、製品コードとは別の**試験用構造**である。元の合成資料に着想を得た架空候補だけを扱い、SUI/SHO/SEIの実API契約にしない。

- H01：推奨まで観測した候補。ただし**Owner受理ではない**。
- H02：検索されているが**提示されなかった**反証候補。これを「不存在」「Owner拒否」と表示したら誤り。
- H03：提示・評価されたが**推奨されなかった**候補。未推奨は不正解や正式却下ではない。
- H04：保存されたが**検索されなかった**未決候補。検索されなかった理由は未検証。
- 正常traceの段階別件数は `4→4→3→2→2→1`。これは出力選択の**事例**であり、認知Methodの成果測定ではない。

チェックは、段階間で出現候補が突然増える／run内のclosed範囲がないのに「ない」と主張する／未提示をOwner棄却と書く／推奨を人の受理とする、を拒否する。実際の候補の意味・選択が適切かは判定しない。

### 実行（Python 3、外部依存なし）

```bash
cd research
python -m unittest -v test_yi_selection_surface.py
python check_yi_selection_surface.py
```

このテストは**候補選択のための汎用プラットフォーム**を作るものではない。異なる意味の「ない」を一つに畳み込む危険を、実験方法の段階で検出するだけである。

## 6. 非線形の再探索と、分母が分かる範囲

この合成Checkerが表すのは、**一つのrunで観測可能な候補集合を段階別に写し、後段の集合が前段の部分集合であるケース**だけである。発想そのものが常に線形な漏斗で進むと主張しない。

- **再発見**：一度提示されなかったH02が、別の問い・Source・Session・AIから再び現れることは正当であり得る。前runの拒否や採用の意味を黙って持ち越さず、新runの同一性、入力、根拠、変化の理由を記録する。単なる同じローカルIDは同一意味の証明にならない。
- **分岐と合成**：複数のカードから新しい仮説が生まれた場合、旧集合の部分集合では表現できない。由来の辺や新しい生成イベントを元のSUI/CSW Ownerの方法で観測する。**本CheckerをProduct実装の普遍的な状態機械として採用しない**。
- **内部候補**：`generated`は、この合成runに**出力され観測された生成候補**を指す。モデルの不可視な内部思考、まだ表示されなかった可能性、別文脈で生成し得る案の数を含まない。
- **閉包の扱い**：`closedForRun=true`はfixture作者による「このrunのこの段階を閉じて記録した」という**宣言**であり、外部ログの独立した網羅証明ではない。閉包の根拠が確認できなければ実研究では`unknown`、報告の対象は「観測できた候補」に限る。
- **保持率**：両端の段階がこのrunに閉じていると宣言された場合だけ、`retentionFraction={numerator,denominator}`と`droppedObservedIds`を示す。片側でもopenなら**N/A（not_qualified）**とし、0%、100%、全探索の網羅率には置き換えない。分母が0のときもN/A。失敗したtraceから成功らしい統計を出さない。

この節の区別は、TEIの[Workspace sources診断 #2823](https://github.com/hat47x/tei-platform/issues/2823)の「列挙されたファイル」と「validateが実際に読んだ対象」が異なる問題にも対応する。**判定がPASSしたか**と**何を評価したか**は異なる。ただしTEIのSource契約へ本Checkerの段階名を移植しない。

### 既存SUIに接続する場合の観測境界（候補・NOT RUN）

TAI mainには、SUIの`/context/query`と`/context/bundle`を読出し・検査する既存参照ハーネスがある。2026-11-06時点の限定的なreceiptは[query](https://github.com/hat47x/tai-pleroma/blob/51196bc941609f5a9dfaafa7afb0ef2c6ed2dd0f/evaluations/records/SUI-TEI-context-2026-11-03.json)と[bundle](https://github.com/hat47x/tai-pleroma/blob/51196bc941609f5a9dfaafa7afb0ef2c6ed2dd0f/evaluations/records/SUI-TEI-context-bundle-2026-11-03.json)にある。

- `/context/query`：accept、preview未確認、未知キー、depth範囲の検証を確認。**カード全数の検索、モデルの生成候補の観測、重要な反証の提示率**を確認したものではない。
- `/context/bundle`：同じクエリ・合成stubでのbundle hash決定性を確認。**実文書の選択品質、元資料の意味受理、社会的合意**を確認したものではない。
- この二つのreceiptを、そのまま`generated/captured/searched/presented`の分子・分母に**対応付けない**。実験では、固定したSUI Document/Card、許可された読出しとSafeMode、出力された候補IDを独立して照合する必要がある。

最初の試行は、固定した合成カードに**反証候補1件と保留候補1件**を含め、(A)カードを直接読む、(B)既存SUIの許可済み集約・読出しを使う、の2条件で比較する。入力SHA・query・filter・実際に返ったID・preview承認・提示されたIDを残す。公開・書込み・新権限は不要。反証候補が見えなくても、UIの非表示、取得制約、意味的選別、未記録のどれかを確認せず「SUIが排除した」とは判定しない。AIの内部思考記録や非公開原文を取得しない。

**実験のGoldと評価**：候補の重要性は実行した製品と独立した担当者が事前に固定する。方法A/B/CやRQ6の既存比較を上書きせず、まず同じrun内の候補ID一致と閉包の観測可能性だけを扱う。未知の分母を補完して改善率を出さない。

## 6. 適用規模と次の最小Gate

| 規模 | 具体的な問い | 既存Ownerとの関係 |
| --- | --- | --- |
| 個人 | 一人の研究・創作で、AIが採用しなかった案に戻れるか。再探索の負担は妥当か | 本人の選好・私的記録と公開を本人が決める。TAI #167/P-06と重複実装しない |
| 組織 | 多数意見に集約した設計レビューで、重大な少数反証が評価前に消えていないか | 承認者の決定と、SUIの意味形成は別。TAI #422の価値レビューに候補だけ渡す |
| 社会 | 複数団体が異論を出す場で、提示されなかった意見を「誰も言わなかった」と扱わないか | 参加権・公開・異議・正当な手続は独立した制度/Ownerの責務であり、本traceで認証しない |

- **G0（本PR）**: 合成traceの構造チェック、誤った不存在・Owner受理の主張を負例で拒否。source-staticとsynthetic構造検査を区別。
- **G1（未実施）**: 既存SCN-001とSUIのカードを利用し、同一入力の要約A/BでH02のような反証の到達を人の独立評価で観測。元資料・版・公開可能性の確認が先。
- **G2（未実施）**: CSWの生成・批評・媒介を異なる条件で導入して、提示選択の効果を分離。第三者評価・モデル差・実負担を測る。
- **Owner判断**: 成果が示されたときだけSUIの保留、SHOの出典、SEIの再開の**既存要件**へ差分を提案する。新しいYI共通Schema、中央記録Store、実行権限は設けない。

**非目標**：生成AI内部の不可視な推論ログを回収すること、候補全体の存在論的網羅を証明すること、媒介者がOwnerの代わりに採否を決めること、全候補の常時記録・公開、モデルの創造性の合成fixtureによる採点。
