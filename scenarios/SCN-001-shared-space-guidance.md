# SCN-001 共同利用スペースの案内改善

状態: **Draft（実証計画・未実行）**  
対象: 架空の共同利用スペース。実在の利用者・施設・規程には関係しない。

## 利用者が達成したいこと

利用者が施設の利用条件を理解し、矛盾する案内を適切に扱い、確認可能な案内文を作り、次の更新時にも過去の判断をたどれるようにする。主体が個人、組織、社会のいずれでも、知的活動としての基本形を比較できることを目指す。

初回の具体的な実行単位は「小規模な共同施設の案内担当者が、会議室予約の要否に関する矛盾を解消しようとする」一件とする。**業務規程の確定、公開・送信、予約の実行は含めない。**

## 入力となる架空の観測

| ID | 入力の内容 | 現段階での扱い |
| --- | --- | --- |
| O-01 | 利用者メモ「会議室の予約が必要か分からない」 | 発言の記録。規程の証明ではない |
| O-02 | 掲示の写し「施設の利用は予約不要」 | 掲示の記載。現行性は未確認 |
| O-03 | 旧案内文「会議室の利用には事前予約が必要」 | 旧文書の記載。現行性は未確認 |
| O-04 | 窓口メモ「会議室だけ予約が必要と案内された」 | 伝聞・再確認待ち |
| O-05 | 提供された資料に予約の承認者が見当たらない | **確認した資料の範囲**での未発見。権限者の不存在ではない |

各入力について、原文、出典種別、取得した時点、出典版（分かる場合）、確認状態を保持する。O-02とO-03の食い違いをどちらか一方の正しさに自動変換しない。

## 最小の知的循環

1. **把握**：O-01〜O-05を個別に保持し、資料の不足と矛盾を把握する。
2. **理解・仮説**：H-01「掲示が古い」、H-02「旧案内文が古い」、H-03「区画によって条件が異なる」を候補として提示する。現時点で採用済みの仮説はない。
3. **明示化**：どの資料にどの仮説が依存するか、どの点が未確定かを記述する。規程と権限を確認する必要性を残す。
4. **成果物**：暫定の案内文（Draft）を作る。例：「会議室の予約要否について資料間に差異があります。管理担当者に確認中です」。確定した案内としての公開は保留する。
5. **判断**：権限を持つ担当者が、根拠を確認したうえで採否・修正を記録する。担当者が不明なら「未決」のままにする。
6. **再観測・更新**：新しい資料O-06が来た場合、旧版の観測や判断を上書きせず、差分、再確認対象、次版の案内案を示す。

**静的な価値**は、観測、仮説、規則候補、判断と文書版を再構成できること。**動的な価値**は、新たな入力からその関係を更新し、判断・制作・再評価へつなげられることにある。

## 意味と権限の境界

- 観測 ≠ 解釈 ≠ 提案 ≠ 承認 ≠ 実行 ≠ 結果。
- 文書案ができた事実は、案内内容の正しさや公開承認を意味しない。
- TEIのモデル候補は、施設の正式な規程や業務効果の受理を意味しない。
- AI、文書生成器、EKIの実行結果は、担当者の意味判断や公開権限を代行しない。
- 例えばO-06の追加で、観測された文面が A → B → A に戻っても、以前の承認の有効性は自動復活しない。承認対象の版・根拠・期間・権限を改めて確かめる。

## 規模を変えるときの再利用範囲

- **個人**：自分の作業・生活上の資料の矛盾を整理し、自分で確認・判断する。
- **組織**：案内の更新に担当者と承認権限を対応づけ、既存業務規程との整合を確認する。
- **社会**：複数組織・住民などの出典、異議、公開範囲と正統な意思決定主体を明示する。

各規模で同じ知的循環を検討できる一方、権限・公開範囲・プライバシー条件は対象ごとに異なる。共通化の採否は別途評価する。
