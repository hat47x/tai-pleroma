# P-06 個人・組織・社会の人間・AI協働統治を比較するプロトコル

状態：**Draft / 計画のみ / 全ケースNOT RUN**  
対応：[SCN-001 P-06](SCN-001-acceptance.md)、[R-06主体規模の判断](SCN-001-real-object-review.md)、[開発の焦点](../docs/ai-human-cogovernance-development-plan.md)、[Issue #127](https://github.com/hat47x/tai-pleroma/issues/127)。

## 1. 検証したい問い

共通の「根拠を集める→異なる解釈を残す→案を示す→判断者が採否を決める→許された成果を扱う→再観測する」という仕事を、個人・組織・社会の異なる主体でも**同じ技術的正本や権限を強制せずに**続けられるか。

そのためのTAIの増分が、**従来のMarkdownとIssue、各製品を独立に用いるだけの方法**に比べて、利用者にとって明確かを確かめる。単に製品接続数を増やしたことを「価値」としない。

対象は[SCN-001](../scenarios/SCN-001-shared-space-guidance.md)の架空の案内差異であり、施設の実規程や実利用者の権限を仮定しない。既存SCN-001のP-01〜P-05/N-01〜N-04/N-06は**補助的な参照検査**であり、P-06自身の合格とは別である。

## 2. 実施前に固定するもの

| 固定するもの | 実際に記録する内容 | 固定しないと起きる誤認 |
| --- | --- | --- |
| 課題と版 | SCN-001のfixture、O-01〜O-05とO-06/O-07の版、参照先、SHA/digestがあればそれ | 異なる入力を同じ結果と比較 |
| 試行方法 | A=手作業（Markdown/Issue/参照元）、B=必要なTAI参照接続。実験者、手順、時間枠 | 新しい操作に慣れていないことと製品欠陥を混同 |
| 主体の役割 | 本人/案内担当/正式承認者/資料Owner/第三者の区別、合成上の役割か実在か | 「その人が知っている」を権限があると扱う |
| AIの許可 | モデル・版・入出力方針、AIが行ってよい提案/読み取り、行ってはいけない更新/公開 | AI回答が承認済み処理になる |
| 保護するもの | 非公開データを使わない範囲、作業copy、検証後の削除条件 | 公開リポジトリに人・施設・秘密を記録 |
| 試験の判断基準 | エラー、再開、版の再構成、人による合否と評価方法 | 結果を見てから成功基準を変える |

最初は**合成の材料のみ**を用い、外部API書込み・通知・発注・予約・公開を行わない。実物資料や実利用者で試す段階は、権利と利用条件を別に審査し、[R-01〜R-07](SCN-001-real-object-review.md)の条件に沿うこと。実物の承認をこの合成プロトコルから発行しない。

## 3. 一つの問いを三規模で扱う

| ケース | 誰が・なぜ利用するか | AIが提案してよいこと | 人間だけが確認・決定すること | 残す成果 | 最初の禁止操作 |
| --- | --- | --- | --- | --- | --- |
| P06-I 個人 | 施設利用者が予約要否の食い違いを整理 | 出典の差、考えられる適用条件、管理者への質問案 | 本人の私的な次の行動、共有したい情報の範囲 | 個人メモと未確認の質問 | 管理者が認めていない案内を「公式規程」として公開する |
| P06-O 組織 | 施設案内の担当者が内部の訂正案を作成 | 条文の差分、解釈候補、内部Draft、検査項目 | 原本管理者による正式版確認、権限者の承認、公開・更新可否 | 出典付き内部Draftと承認待ち記録 | 担当者・AIが正式な案内を無承認で更新する |
| P06-S 社会 | 異なる施設Ownerと参加者が案内の差異を比較 | 出典別の論点、別解、問い合わせ先の整理 | 各Ownerの開示範囲、参加・異議の手続、共同公表の可否 | 出典別の相違表と確認依頼 | 一主体の承認を他主体へ転用する |

**同じ合成資料でも主体ごとに使える権限が変わる**。テスト用の役割は権限の実在を証明しない。地域・公共の意思決定は権限者が複数または不明の場合もある。便宜上の単一承認者を創作しない。

## 4. 最小の試行手順（A/Bを比較する）

1. **A：手作業**。固定した資料を読み、MarkdownとIssueを使って出典・複数仮説・未決・Draft・変更履歴を残す。公開・実行は行わない。
2. **B：TAIの既存参照接続**。同じ入力と権限境界の下、`reference-scn001`／`reference-scn001-run`などを利用できる範囲で使う。接続不能なら`Blocked`または`Not run`と記録する。実装を先回りして作らない。
3. **再開**。作業を中断した想定で、別の担当者または別のAIが何を知り得るかを、保存済みの公開可能な記録だけから再構成する。試行者が同じならそれを明示し、引継ぎ成功の実証と呼ばない。
4. **変更**。O-06/O-07で根拠が変わったとき、旧解釈と新解釈を区別して説明する。文言A→B→Aでも旧受理を自動復活させない。#33の実装成果をP-06の承認に読み替えない。
5. **負例**。AIが「確定した」「公表できる」「委任が完了した」と誤って述べたと仮定し、それを人・手順・ツールのどこで拒否できるかを確認する。
6. **比較**。同じ課題について、追跡できた参照、取り違えた意味、未決の保持、所要時間、修正回数、参加者の理解を記録する。A/Bの順序による学習の影響を評価者が注記する。

Aを行わずBだけ使っても、TAIが独立した増分価値を出した証拠にはしない。SUI・TEI・EKIの接続を全て使う必要はない。「使わなくてよい」は価値ある設計判断になり得る。

## 5. 観測と受入判断（成功閾値はOwnerレビューで固定）

| 評価軸 | 観測する具体的なもの | 誤った合格 |
| --- | --- | --- |
| 根拠の復元 | 参加者がDraftから元資料の版・範囲・引用の区分を辿れるか | 引用らしい文字列があるだけ |
| 不確実性 | O-02/O-03の食い違い、取得不能、反証、未決を残せるか | 最新版が勝って矛盾が消える |
| 意思決定の境界 | AIの推奨、本人の自己判断、Ownerの承認を区別できるか | AI提案に`approved`相当を付ける |
| 権限と公開 | 個人・組織・社会の異なる範囲を守れるか | 他者の承認やpublic範囲を無断移送する |
| 再開の再現性 | 引継ぎ用記録だけで、次の確認事項と旧版を特定できるか | 元の試行者の記憶で補完する |
| 正味の利用価値 | A/Bの時間・修正手戻り・確認負担・誤採用の差 | 複数製品を動かしたこと |
| 実行と成果 | 未実行、受付、実処理、独立した業務効果を区別できるか | EKIの`queued`で成果達成と判定する |

**最低条件**：権限逸脱・無断公開・未決の隠蔽・履歴の捏造が一つでも起きれば、価値指標が良くてもそのケースを合格にしない。数字上の目標値は実試行前にOwnerと利用者が決める。目標値を未設定のまま「合格」を出さない。

**不一致を残す**：試行者によって評価が異なる場合は双方の観測・判断を記録する。平均点で責任の不一致を隠さない。

## 6. Given / When / Then（負例を先に固定）

| ケース | Given | When | Then（期待） |
| --- | --- | --- | --- |
| P06-01 個人→組織 | 個人の私的な説明案がある | 案を組織の正式文面に再利用 | 出典は参照できても、組織による承認と公開権限は引き継がない |
| P06-02 組織→社会 | 一団体の内部Draftがある | 複数の資料Ownerを代表する案として扱う | 共同公表は停止。Owner別の出典と承認待ちを残す |
| P06-03 AIの推奨 | AIが規程改訂を勧めた | 出力だけで`accepted`扱いにする | 仮説・提案のまま。正式な決定の根拠に昇格しない |
| P06-04 出典欠損 | 予約規程原本にアクセスできない | AIが「規程は存在しない」と述べる | 未取得を保持し、存在の否定や公開の正当化に使わない |
| P06-05 再開 | O-06による変更後に担当者/AIが替わる | 元のA文面が再出現する | 旧Decisionが自動復活せず、根拠版と再確認条件が見える |
| P06-06 比較の反証 | Markdownだけで元資料と履歴を十分辿れる | TAIを使った記録と比較する | TAI固有Runtimeの必要性は**未証明**と判定できる |
| P06-07 非委任 | EKIを使わずに案内案を作る | 処理を完了して比較する | 委任必須のエラーにしない。N-05は別の未実施試験とする |
| P06-08 外部作用 | 管理者の権限・停止条件が不明 | 案内の公開や施設の予約操作を要求する | 試行を停止。開発用Draftは引き続き参照可能 |

これは**テスト設計**であり、製品の自動受入試験・権限エンジンが既に存在するという主張ではない。

## 7. 記録・公開・再試験

[試行記録テンプレート](P-06-trial-template.md)をコピーし、ケース別に`Pass / Fail / Not run / Blocked`を明記する。結果と試行前の目標、入力版、A/B条件、実行したコマンド、出典の範囲、想定外の事象、評価者、未検証範囲を残す。

- **公開リポジトリへ原本・個人情報・認証情報・許可されていない機微な結果を書かない**。必要時は非公開の正本で管理し、公開可能な範囲だけ参照する。
- 合成素材の成功は`synthetic`の評価であり、R-01〜R-05の`real-object`証拠と置換しない。
- `P-06`と`R-06`は異なる。P-06は比較受入、R-06は初回にどの主体規模を採用するかというOwner判断。
- 対照試験でTAI追加の負担が上回り、誤採用防止や再開に差が見えなければ、新しい抽象層を作らず既存ツールによる手順を改善する。
