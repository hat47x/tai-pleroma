# テストが暗黙にホストを選ぶ問題（YIC横断記録）

状態: 観測の記録（2026-11-16）。設計の提案ではなく、実行して分かった事実の整理である。

本資料は、YIC実行票と横断計画が「PASS」「未確認」と書いてきた箇所のうち、**実行ホストによって結果が変わるもの**を集めたものである。目的は一つである。**「CIが緑」と「手元で検証済み」を同じ緑として数えない**ための材料を揃える。

## 1. 何が起きたか

YICの実行票が「未実行」としていたテストを実際に走らせたところ、3製品で**同じコードがホストによって別の結果**を出した。

| 製品 | 対象 | Windows | Linux | 原因 |
| --- | --- | --- | --- | --- |
| TEI | `internal/workspace` パス境界 3件 | **SKIP 2件**、PASS 1件 | **PASS 3件** | symlink作成権限が無い。open-file renameの意味が異なる |
| TEI | `cmd/tei` self-build 1件 | **SKIP** | **PASS**（subtest 5件） | `runtime.GOOS != "linux"` で固定 |
| SUI | `tests/test_r2_source_snapshot_read_gate.py` 70件 | **FAIL 70件** | **PASS 70件** | `os.open(directory, O_RDONLY)` を Windows が拒否。一時名が MAX_PATH 超過 |
| SEI | `runtime/go` 16パッケージ | **PASS 16** | （未実行） | 差は見つかっていない |

根拠のreceipt: [TEIパス境界](../../../evaluations/records/YIC-tei-rooted-source-2026-11-16.json)、[TEI self-build](../../../evaluations/records/YIC-tei-linux-regression-2026-11-16.json)、[SUI gate](../../../evaluations/records/YIC-sui-r2-gate-hosts-2026-11-16.json)。

## 2. SKIPとFAILは違うが、どちらも「未検証」

三つの結果は、どれも**そのホストでは対象の性質が確かめられていない**という点で同じである。

- **SKIP**: テスト自身が「このホストでは意味がない」と判断して降りた。`go test`は`ok`と表示し、終了コードは0である。**サマリ行だけ見れば緑**に見える
- **FAIL**: 対象のコードが壊れているのではなく、**対象OSで成立しない前提**（ディレクトリのfsync、パス長）に当たった。赤だが、包含ロジックの破損ではない
- **PASS（linux）**: 対象の性質がそのホストで成り立つ。ただし**別OSへ転記できない**

したがって「テストが存在する」「CIが緑」の二つは、**どのホストで何が確かめられたか**を伴わない限り、証拠として弱い。

## 3. とくに危ない組み合わせ

この3件は、いずれも**安全性・耐久性の検査**である。

| 検査 | 何を守るか |
| --- | --- |
| symlink脱出の拒否 | root外のファイルを読ませない |
| open-fileのrename跨ぎ固定 | 差し替えられたファイルを読まない（TOCTOU） |
| ディレクトリのfsync | 書込みが永続化されたと誤認しない |
| computeの再現性（self-build） | 同じPlanから同じ成果を期待しない |

**いずれも「Windowsで通った」とは言えない種類**である。とくにSUIの70件は、Windowsで実行すると**全滅する**。これを「壊れている」と読むのも、「linuxで緑だから大丈夫」と読むのも、どちらも誤りである。

## 4. 実務への影響

### 4.1 実行環境を明示する

テスト結果を記録するときは、少なくとも次を残す。

- `GOOS`/`GOARCH`（Go）または実行OS（Python）
- ツールチェーンの版（例: `go1.26.11 linux/amd64`）
- SKIPした件数と、その理由の文字列
- FAILした場合、**それが対象の欠陥かホストの制約か**の切り分け

本資料のreceiptは、いずれもこれを含む。この点検は機械化した（[点検のreceipt](../../../evaluations/records/YIC-skip-disclosure-2026-11-16.json)）。

- 個々の検証判定を持つYIC receiptは、**実行ホストを明示**する（`hostGoos`/`hostGoarch`/`goVersion`/`hostKernel` など）
- SKIPを含むreceiptは、**そのSKIPを可視にする**（件数または理由）
- `ok`と終了コード0だけを根拠にした「通った」を残さない

点検の途中で、`YIC-tei-rooted-source`が両ホストの判定を持ちながら**ホストを記録していない**ことが分かったので、生成側にWindowsとLinuxの両方の版を記録するよう足して再生成した。

### 4.2 「全件実行」を一律に要求しない

ホスト差がある以上、**単一ホストでの全件PASSを唯一の合格条件にしない**。代わりに、次を分けて記録する。

1. そのホストで実行できた件数
2. SKIPした件数と理由
3. 別ホストで確認済みの範囲（receiptの参照）

### 4.3 CIの緑を、手元の検証の代用にしない

CIがlinuxで回っていることは、**linuxでは確かめた**という意味である。Windows利用者の手元で同じ性質が成り立つかは別で、本資料の3件はそこが空いていた。

## 5. この記録が示さないこと

- 対象コードの欠陥の有無（ホスト差は欠陥の証拠でも、無欠陥の証拠でもない）
- 別ホスト（macOS等）の挙動
- 実Productの認可・開示・Consumer受領
- 各テストが測ろうとしている性質の、テスト以外での成立

## 6. 変更履歴

- 2026-11-16 初版。TEI・SUI・SEIのテストを実際に複数ホストで走らせ、SKIP・FAIL・PASSの意味を分けて記録した。
