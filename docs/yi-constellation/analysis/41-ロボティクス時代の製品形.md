# ロボティクス時代の製品形

状態: 構想（2026-11-02）。生成AIがインフラとして普及した社会を前提とする。製品の形の提案であり、実装、採用、安全認証の約束ではありません。

## 1. インフラの層

インフラ産業は、クラウドだけではない。電力、通信、計算、データの層がある。ロボットは、電力と通信の上で動き、計算とデータの上で考える。系列は、その上に立つ。

生成AIも、この層の一つになりつつある。電気、通信、計算、データの上に、生成AIの層が加わる。生成AIは、特別な製品ではなく、当然の前提であり、インフラである。系列は、その上に立つ。

系列は、インフラを競わない。電力を作らず、通信を敷かず、計算基盤を持たない。系列は、インフラの上で、記録と受け渡しの通路を作る。

インフラに依存しないために、系列は次の条件を持つ。

- エッジとクラウドの分割。すべてをクラウドへ送らない。現場で閉じる記録と、クラウドで集約する記録を分ける。
- 低電力と断続接続。通信が途切れても、記録が失われない。
- データの所在。国や地域の規制に合わせて、記録の置き場所を選べる。
- 電源の制約。バッテリーで動くロボットの記録は、送信の頻度と量を制御できる。

夬の九五の「中行」は、インフラ産業の位置である。極端に走らず、中央の道を保つ。系列は、その中央の道の上で、統合と業務適用を担う。

## 2. TAI プロトコルとソフトウェア

TAIの核は、ソフトウェアの画面ではなく、受け渡しのプロトコルである。誰が、誰に、何を、どの権限で、どの安全エンベロープの下で渡すか。その形式と規則が、TAIの本体である。

プロトコルの最小の項目は、次のとおりである。

```
handoff_id, task_id, from, to,
actor_type (human / robot / system / ai),
actor_id, authority_ref, safety_envelope_ref,
sent, not_sent, ack, next_action, deadline, evidence_ref
```

ソフトウェアの形は、このプロトコルの参照実装である。薄い画面、ライブラリ、サービス、文書のどれでもよい。画面がなくても、プロトコルが守られれば、TAIは機能する。

ロボットは、この構造を大きく変えない。変わるのは、行為者の種類と、安全の項目である。ロボットが行為者になると、actor_typeにrobotが加わり、safety_envelope_refが必須になる。権限の参照は、ロボットの運用権限と、人の承認権限に分かれる。

いま作る最小の核は、プロトコルのスキーマと、参照実装である。将来課題は、複数台のロボットの受け渡し、ROS 2のアクションとの対応付け、安全認証された制御器との接続である。

## 3. SUI ロボットの欄と来歴

SUIがロボットの欄を持つのは、ロボットの物理的、電子的な存在特性を記録し、カードの声の位置づけを明確にするためである。

ロボットの欄には、ロボットID、機種、ファームウェアの版、センサーの構成、位置、動作モード、安全の状態を含める。声のカードが、どのロボットの、どの状態の下で置かれたかが分かる。

情報記録者のアイデンティティと来歴も、従来より多様になる。人、ロボット、AIエージェント、センサー、組織。記録者ごとに、次の項目を持つ。

- 記録者の種類。
- 記録者のID。
- 出所。
- 時刻。
- 位置。
- 権限。
- 確度。
- 添付の媒体。

カードの配置は、従来の二次元の板から、三次元空間、生成画像、動画、身体動作支援、五感全体へ広がり得る。ただし、カードと文章による情報保持の形を捨てる必要はない。むしろ、テキストのカードが、生成の基盤、中心、根幹になる。三次元の配置も、動画も、身体動作も、テキストのカードを参照する表示である。

いま作る最小の核は、来歴の項目と、ロボットの欄である。将来課題は、三次元空間の配置、生成画像と動画の添付、ウェアラブルデバイスからの身体動作の記録、五感の記録である。

## 4. SHO Markdownの核と、3D・動画・ウェアラブル

SHOは、現行のMarkdownエディタの延長線上でよい。原本から手順を作り、文ごとの出所を付ける。この核は、ロボティクス時代も変わらない。

ロボティクス時代のマニュアルと作業指示は、Markdownの核に、次の要素を加える。

- 手順の段階と、各段階の安全の制約。
- 道具、部品、ロボットの動作の参照。
- 原本の版と、手順の版の対応。
- シミュレーションの証拠。
- 写真、動画、三次元モデルの添付。

三次元VRのマニュアル、動画のサポート、ウェアラブルデバイスによる人間動作支援は、Markdownの核の表示と拡張である。手順の正本は、テキストのMarkdownに置く。三次元も、動画も、ウェアラブルも、テキストの手順を参照する。

いま作る最小の核は、原本から手順への変換、文ごとの出所、参照範囲の対応表、生成前の検査である。将来課題は、三次元VRの表示、動画の添付、ウェアラブルからの動作支援、シミュレーションの証拠との接続である。

## 5. SEI ロボットを行為者として

SEIの個人、組織、社会の位置づけに、ロボットがそのまま入る。ロボットは、個人の道具であり、組織の行為者であり、社会の構成員である。

AIモデルが組織を体現することと、ロボットが組織を体現することは、似ている。どちらも、委任された権限を持ち、組織の判断を代行し、その行為の理由を問われる。SEIは、この二つを、同じ判断の記録の形式で扱う。

ロボットの判断の記録には、次を含める。

- ロボットID、機種、ファームウェアの版。
- 行為と、その理由。
- 選択肢と、判断の基準。
- 権限の参照。運用権限と、人の承認権限。
- 前提と、安全の制約。
- 根拠と、シミュレーションの証拠。
- 人の監督者と、介入の記録。
- 再検討の条件。

時系列データの保持は、外部のプロダクトに委ねてよい。SEIは、時系列の中から高次の意味を見出し、生成的な作用をもたらす情報へ統合し、共有する。記録の量ではなく、記録から何を生むかが、SEIの強みである。

いま作る最小の核は、ロボットを行為者とする判断の記録である。将来課題は、センサーの時系列との接続、リアルタイムの動作ログの取り込み、規制ごとの監査テンプレート、複数台のロボットの判断の比較である。

## 6. TEI ロボティクス設計環境

TEIは、そのまま、過大な複雑性を持つロボットの設計から実装に使える。ロボットの周辺世界を支えるシステムの構築にも使える。TEIは、もともと汎用の開発環境として構想され、組み込み系の利用も想定している。

TEIの核は、意味の対応表と、位置の検査と、失われるものの一覧である。ロボットの設計では、次の対応を扱う。

- 要求から、設計への対応。
- 設計から、実装への対応。
- 実装から、試験への対応。
- 旧システムから、ロボットシステムへの対応。
- 役割と権限の対応。

ROS 2の対応は、将来課題として明確に含める。ワークフロー標準とデジタルツインは、プラグインで拡充できる。基本データ構造には、ロボティクスで扱うデータ構造を網羅する。三次元の変換、センサーのデータ、アクションの目標と結果、安全の状態、ロボットのモデル、シミュレーションの資産。UIの可視化は、順次揃える。

いま作る最小の核は、意味の対応表、位置の検査、失われるものの一覧、承認の印である。将来課題は、ROS 2のプラグイン、URDFとTFの取り込み、センサーデータの型、三次元の可視化、デジタルツインとの接続である。

## 7. EKI ロボットの余力

EKIは、ロボットの余力を、ソフトウェアとして具現化する。余力には、次の種類がある。

- 遊休時間。
- 計算能力。
- バッテリーの余り。
- 搭載能力。
- 保管空間。
- 充電の枠。
- 移動能力。
- センサーの時間。

ソフトウェアの最小の核は、提供、依頼、組み合わせ、返りの記録である。提供には、資源の種類、量、制約、期間を含める。依頼には、必要、量、期限を含める。返りには、報告、修正、貸し、労力、学習を含める。安全エンベロープは、交換の条件に含める。

物理世界を絡めた構成は、将来課題である。充電の枠の共有、保管空間の共有、移動能力の共有、複数拠点のロボットの余力の共有。これらは、安全の制約と、責任の配分と、市場の仕組みに依存する。

いま作る最小の核は、余力の交換の記録と、安全の制約と、返りの経路である。将来課題は、物理世界の構成、複数拠点の共有、市場の仕組み、責任の配分である。

## 8. 生成AIはインフラであり、次はロボティクスである

生成AIは、当然の前提であり、インフラである。電気、通信、計算、データと同じ層に置かれる。特別な製品ではなく、社会の基盤として普及する。生成AIの有無を問うのではなく、生成AIがあることを前提に、何を作るかが問われる。

モデルベンダーが成長の主役だった時代は、夬で決する。モデルは製品からインフラへ移る。バブルが消えても、生成AIは消えない。電気が普及した後も、電気が残るのと同じである。生成AIも、同じ道をたどる。

系列は、生成AIを前提にする。モデルの性能を競わない。モデルは、交換できる部品として扱う。系列の資産は、モデルではなく、記録とプロトコルと通路である。モデルが替わっても、記録の形式が変わらなければ、系列は機能する。

ロボティクス時代は、生成AIのインフラの上に立つ。ロボットは、生成AIを脳の一部として使い、電力と通信の上で動き、計算とデータの上で考える。系列の役割は、ロボットと人と組織の間の通路である。

ロボティクス時代の予測は、現代の知見でも、それほど大きなギャップがない。予測可能な世界観の枠内にある。だからこそ、いまから備えられる。生成AIの標準を待つのではなく、記録の形式をいま作り、ロボットの標準が来たら、アダプターで対応付ける。

系列の核は、生成AIの時代も、ロボティクス時代も、変わらない。誰が、誰に、何を、どの権限で、どの安全の下で渡すか。その記録と通路である。変わるのは、行為者の種類と、安全の項目と、媒体の形である。

系列は、生成AIを既済にしないために存在する。生成AIがインフラになっても、最終的な権威にはしない。ロボティクス時代にも、同じ目的を持つ。ロボットを完成させず、開いておく。ロボットを最終的な権威にせず、人の道具として保つ。ロボットの行為の理由を残し、人の介入を記録し、次の問いを残す。

自動運転をロボティクスの前段として読む枠組みは、[42-自動運転の枠組み](42-自動運転の枠組み.md)に置きました。

## 10. 境界

- 本資料は、製品の形の提案です。実装、採用、安全認証の約束ではありません。
- ロボティクス時代の予測は、シナリオであり、時期や勝者の予測ではありません。
- 系列は、安全制御器でも、リアルタイムの制御プレーンでもありません。記録と受け渡しの層です。
- 電力、通信、計算、データのインフラは、系列の外にあります。系列は、インフラに依存しない記録の形式を作ります。
- 定量化、指標、検証は、本資料の対象外です。
