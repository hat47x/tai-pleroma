# SHOの扱い

状態: 判断用の整理（2026-11-01）。決定ではありません。採否はOwnerが決めます。

本資料は、SHO Composerを製品として扱うか、MMIの役割として統合するか、名前だけの枠として保留するかを、今分かっている証拠から整理します。[20-製品と卦の対応レビュー](20-製品と卦の対応レビュー.md)で、SHOと升の対応を弱いとしました。その判断を受けて、選択肢と影響をまとめます。

## 1. いま分かっていること

- `sho-composer`のリポジトリには、LICENSEと初期コミットしかない。README、要求文書、実装、Issueがない。
- MMIのADR-0024は提案中であり、製品名、リポジトリ名、拡張ID、npm名は変わっていない。
- 概要資料は、SHO Composerを製品1/6として提示し、注記でSHOが現行のMMIを含む役割として整理されていると説明している。
- [02-認知面の卦読み](02-認知面の卦読み.md)は、SHOを升として読み、積むことと漸進を中心に置いている。
- [05-要件候補](05-要件候補.md)は、RQ-YI-005（昇の上限）とRQ-YI-006（昇の来歴）をSHOに割り当てている。
- [11-新規領域](11-新規領域.md)は、SHOの相の拡充として、空邑の検出と冥升の修復を挙げている。
- [20-製品と卦の対応レビュー](20-製品と卦の対応レビュー.md)は、SHOの対応を弱いとし、升の読みを製品の説明ではなく仮説として扱うべきだとしている。

つまり、製品の物語は先にあり、製品の定義が後から付いていない状態です。物語を否定する証拠はありませんが、物語を支える製品側の証拠もありません。

## 2. 三つの選択肢

### 案A 独立した製品として定義する

SHOを、升の卦に対応する独立製品として定義します。

- 必要なもの。README、要求文書、Owner、利用者の入口、MMIと重ならないライフサイクル、升の読みを仮説として検証する計画。
- 仕事。製品の目的を、升の「積」と「漸進」から具体化する。MMIの来歴機能との差分を定義する。概要資料の製品1/6の提示を、定義に合わせて更新する。
- 利点。系列の六製品の物語を保てる。昇りの機能を、独立した価値として育てられる。
- 危険。製品の定義がないまま、名前と卦だけが先に立つ。MMIの来歴機能と重複する。Ownerと利用者が見えないまま、資料だけが先行する。

### 案B MMIの役割として統合する

SHOを独立製品にせず、MMIの来歴と昇りの機能を、MMIの役割として位置づけます。

- 必要なもの。ADR-0024の受理、MMIのREADMEと要求への昇りの役割の追記、概要資料の製品数の変更、RQ-YI-005と006のMMIへの移管。
- 仕事。升の読みを、MMIの来歴層の読みとして書き直す。SHOの名前は、役割名として残すか、消すかを決める。
- 利点。実際に存在する機能と、製品の定義が一致する。六つの製品のうち、一つを役割へ移すことで、製品数の水増しを避けられる。
- 危険。系列の六製品の物語を変える。ブランドと概要資料の変更が大きい。MMIの来歴が、升の読みに耐えるかを確かめる必要がある。

### 案C 名前だけの枠として保留する

SHOを製品としても役割としても確定せず、名前だけの枠として保留します。

- 必要なもの。概要資料とMMIのREADMEに、SHOが構想中であり、製品定義が未確認であることを明記する。升の頁を、製品の頁ではなく仮説の頁として扱う。RQ-YI-005と006を、SHO条件付きの候補として残す。
- 仕事。SHOの定義ができた時点で、案Aか案Bを選ぶ。定義ができないままなら、案Bへ移す。
- 利点。六製品の提示を急に変えずに、証拠の不足を隠さない。G1の他の判断を止めない。
- 危険。保留が長期化すると、名前だけの製品が資料に残る。読み手が、SHOを既存の製品と誤解する可能性がある。

## 3. 判断の基準

1. 製品の定義があるか。README、要求、Owner、利用者の入口。
2. MMIの来歴と重ならないライフサイクルがあるか。
3. 升の読みが、名前の後の正当化ではなく、製品の仮説として検証できるか。
4. 概要資料の六製品の提示を、変える覚悟があるか。
5. 保留する場合、その期間と再検討の条件を決められるか。

## 4. 推奨

G1では案Cを選び、G5までに案Aか案Bを決めることを勧めます。

理由は三つです。

第一に、いま案Aを選ぶと、製品の定義がないまま、名前と卦が先に立ちます。これは、本分析が避けたい事後の正当化になります。

第二に、いま案Bを選ぶと、ADR-0024の受理とMMIの要求の変更が必要になり、G1の他の判断を巻き込みます。MMIの来歴が升の読みに耐えるかも、まだ確かめていません。

第三に、案Cなら、証拠の不足を明記したうえで、六製品の提示を急に変えずに済みます。ただし、保留の期限と、案Aか案Bを決める条件を、同時に決める必要があります。

## 5. 選択肢ごとの影響

### 5.1 製品数と概要資料

- 案A。六製品のまま。スライド2と8の製品一覧を保ち、SHOの頁に定義の進捗を足す。
- 案B。五製品と一役割。スライド2と8の製品数を変え、MMIの頁に昇りの役割を足す。スライド28の升を、製品ではなく役割として示す。
- 案C。六製品のまま。スライド2と8に、SHOが構想中であることを一行で足す。スライド28の升を、仮説の頁として示す。

### 5.2 要求の割当

- 案A。RQ-YI-005と006はSHOの要求として残す。空邑と冥升の相の拡充もSHOに置く。
- 案B。RQ-YI-005と006をMMIへ移す。空邑と冥升は、MMIの来歴層の検査として読み直す。
- 案C。RQ-YI-005と006を、SHO条件付きの候補として残す。MMIで先に試すことは妨げない。

### 5.3 卦の頁

- 案A。升を、SHOの製品の卦として読む。六爻の読みは、製品の仮説として提示する。
- 案B。升を、MMIの来歴層の卦として読む。製品の卦ではなく、役割の卦として示す。
- 案C。升を、製品の卦としても役割の卦としても確定せず、仮説の頁として示す。

## 6. 判断を変える条件

- SHOのREADMEと要求文書が作られ、Ownerと利用者の入口が決まる。この場合、案Aを再検討する。
- ADR-0024が受理され、MMIの来歴が升の読みに耐えると確認できる。この場合、案Bを再検討する。
- SHOの定義が、期限までに作られない。この場合、案Bへ移す。
- 概要資料の六製品の提示を変える決断ができない。この場合、案Cを続けるが、期限を延ばさない。
