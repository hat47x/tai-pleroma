# 四つの記録のスキーマ

状態: 暫定決定（2026-11-02）。生成AIが暫定的に決め、設計と製造を進めるための記録である。実装、採用、安全認証の約束ではない。

## 1. 決定の方法

この資料は、人間の判断を待たずに、生成AIが暫定の意思決定を行い、設計と製造を進めるための記録である。人間はIssueで見解を供給する。生成AIは、その見解を暫定の決定に反映し、得られた知見を計画と設計へ回収する。発生した課題は、上位の設計レベルで統合して解決する。

暫定の決定は、次の三つである。

第一に、記録の形式を、製品に中立なJSONのスキーマにする。モデル、車両、ロボットのベンダーに依存しない。

第二に、系列は安全制御器でも、リアルタイムの制御プレーンでもない。記録は、安全エンベロープを参照するが、安全制御のループに入らない。

第三に、四つの記録を、自動運転とロボティクスの両方で使う。領域の違いは、必須の項目で吸収する。

自動運転は、ロボティクスの前に一律に来る時代予測として置かない。自動運転は参照領域であり、四つの記録は、その記録を読むための観点である。構造の互換は、意味の互換を意味しない。

## 2. 四つの記録

四つの記録は、出来事、受け渡し、判断、意味の対応である。すべてに共通する項目は、次のとおりである。

| 項目 | 型 | 意味 |
| --- | --- | --- |
| schema_version | string | スキーマの版。いまは0.1。 |
| record_type | string | event、handoff、decision、meaningのどれか。 |
| domain | string | adまたはrobotics。 |
| safety_envelope_ref | string | 安全エンベロープの参照。event、handoff、decisionで必須。 |
| evidence_refs | array | 証拠の参照。event、handoff、decisionで必須。 |

### 2.1 出来事の記録

出来事の記録は、ロボットまたは自動運転の行為と結果を残す。

| 項目 | 型 | 必須 | 意味 |
| --- | --- | --- | --- |
| event_id | string | はい | `evt-`で始まるID。 |
| occurred_at | string | はい | 出来事の時刻。 |
| actor | object | はい | 行為者。typeとid。 |
| action | string | はい | 行為。 |
| authority_ref | string | はい | 権限の参照。 |
| safety_envelope_ref | string | はい | 安全エンベロープの参照。 |
| outcome | enum | はい | completed、aborted、failed、takeover、disengaged、incident。 |
| evidence_refs | array | はい | 証拠の参照。 |
| handoff_ref | string | いいえ | 受け渡しの参照。 |
| vehicle_id | string | adでははい | 車両のID。 |
| automation_level | integer | adでははい | 0から5。 |
| odd | string | adでははい | 運行設計領域。 |
| mrc | string | いいえ | 最小リスク状態。 |
| robot_id | string | roboticsでははい | ロボットのID。 |
| robot_model | string | roboticsでははい | 機種。 |
| firmware_version | string | いいえ | ファームウェアの版。 |

### 2.2 受け渡しの記録

受け渡しの記録は、人、ロボット、車両、システムの間で、何を渡し、何を渡さなかったかを残す。

| 項目 | 型 | 必須 | 意味 |
| --- | --- | --- | --- |
| handoff_id | string | はい | `hnd-`で始まるID。 |
| task_id | string | はい | 作業のID。 |
| from | object | はい | 送り手。typeとid。 |
| to | object | はい | 受け手。typeとid。 |
| sent | array | はい | 渡したもの。 |
| not_sent | array | はい | 渡さなかったもの。空でもよい。 |
| ack | enum | はい | accepted、accepted_with_conditions、rejected、no_response。 |
| next_action | string | はい | 次の行動。 |
| deadline | string | いいえ | 期限。 |
| takeover_request | object | いいえ | テイクオーバー要求。requested_atとreason。 |
| safety_envelope_ref | string | はい | 安全エンベロープの参照。 |
| evidence_refs | array | はい | 証拠の参照。 |

### 2.3 判断の記録

判断の記録は、行為の理由、選択肢、基準、権限、前提、安全の制約、証拠を残す。

| 項目 | 型 | 必須 | 意味 |
| --- | --- | --- | --- |
| decision_id | string | はい | `dec-`で始まるID。 |
| action | string | はい | 行為。 |
| rationale | string | はい | 理由。 |
| options | array | はい | 選択肢。 |
| criteria | array | はい | 判断の基準。 |
| authority_ref | string | はい | 権限の参照。 |
| assumptions | array | はい | 前提。 |
| safety_constraints | array | はい | 安全の制約。 |
| evidence_refs | array | はい | 証拠の参照。 |
| revisit_condition | string | はい | 再検討の条件。 |
| supervisor_ref | string | いいえ | 監督者の参照。 |
| disengagement_reason | string | いいえ | ディスエンゲージメントの理由。 |
| mrc | string | いいえ | 最小リスク状態。 |
| safety_envelope_ref | string | いいえ | 安全エンベロープの参照。 |

### 2.4 意味の対応

意味の対応は、移行前後の工程、役割、権限、失われるものを残す。

| 項目 | 型 | 必須 | 意味 |
| --- | --- | --- | --- |
| meaning_id | string | はい | `mean-`で始まるID。 |
| source_step | string | はい | 移行前の工程。 |
| target_step | string | はい | 移行後の工程。 |
| role | string | はい | 役割。 |
| permission | string | はい | 権限。 |
| status | enum | はい | same、split、merged、dropped、new。 |
| owner | string | はい | 担当。 |
| loss_note | string | はい | 失われるもののメモ。空でもよい。 |
| safety_case_ref | string | はい | 安全ケースの参照。 |
| evidence_refs | array | いいえ | 証拠の参照。 |

## 3. 自動運転とロボティクスの拡張

自動運転では、vehicle_id、automation_level、oddを必須にする。テイクオーバーの受け渡しには、takeover_requestとmrcを加える。判断には、supervisor_refとdisengagement_reasonを加える。

ロボティクスでは、robot_idとrobot_modelを必須にする。出来事には、firmware_versionを加える。判断には、安全の制約と、人の監督の参照を加える。

四つの記録の核は、領域で変えない。変えるのは、必須の項目と、参照する安全の制度である。

## 4. 合成fixtureと検証

合成fixtureは、自動運転の概念を模したものに五つ、ロボティクスに四つ置いた。

- 自動運転。テイクオーバーの受け渡し、インシデントの受け渡し、ディスエンゲージメントの判断、インシデントの出来事、旧ECUから自動運転スタックへの意味の対応。
- ロボティクス。ピックアンドプレースの受け渡し、出来事、判断、意味の対応。

検証は、`evaluations/audit-robotics-records.py`で行う。外部ライブラリは使わない。スキーマの必須項目、型、列挙、パターン、追加項目の拒否を確かめ、記録の間の参照と、二つの領域の網羅を確かめる。負例の自己試験も行う。

実行結果は、`evaluations/records/robotics-records-2026-11-02.json`に置いた。合成fixture九件、スキーマ四件、自己試験は通過した。実車、実ロボット、実安全制御器は未検証である。

## 5. 検証から回収した知見

第一に、四つの記録は、自動運転とロボティクスで同じ形で使える。違いは、必須の項目と、参照する安全の制度だけである。領域ごとに別のスキーマを作る必要はない。

第二に、すべての記録に安全エンベロープを付ける必要はない。意味の対応は、行為の記録ではなく、移行の記録である。安全エンベロープではなく、安全ケースの参照を持つ。これは、当初の想定の修正である。

第三に、テイクオーバーの受け渡しには、takeover_requestとmrcが必要である。自動運転の受け渡しは、一般の作業の受け渡しと違い、要求の時刻と理由、最小リスク状態を持つ。

第四に、受け渡しの返答にno_responseを加える必要がある。インシデントの受け渡しでは、返答がないことがある。返答がないことを、拒否と混ぜない。

第五に、判断の記録には、選択肢、基準、前提、安全の制約、証拠を非空で持たせる必要がある。空の配列は、判断の記録として不十分である。

第六に、意味の対応のstatusにsplitを加える必要がある。旧ECUの制動制御は、自動運転スタックの複数の要素に分かれる。splitは、移行の現実を表す。

第七に、構造の互換は、意味の互換ではない。自動運転のODD、MRC、テイクオーバーと、ロボティクスの安全ゾーン、動作モード、人の介入は、同じ項目名で違う意味を持つことがある。本資料の検証は、項目の形が通ることを確かめただけで、意味の同一性を確かめていない。

## 6. 未解決の課題と、上位設計での統合

第一に、リアルタイムの安全と、記録の完全性の緊張である。系列は、安全制御のループに入らない。記録は非同期でよい。安全エンベロープは参照であり、制御ではない。この緊張は、系列を安全制御器にしない、という上位の設計で統合する。

第二に、記録の所有と、安全ケースの所有の緊張である。系列は、安全ケースを所有しない。安全ケースは、安全の責任を持つ組織が所有する。系列は、参照を記録する。この緊張は、系列を通路にする、という上位の設計で統合する。

第三に、モデルに依存しないことと、提供元を記録することの緊張である。actorのtypeにaiを加えたが、提供元のIDと版は、必須にしていない。提供元は、証拠の参照か、拡張の項目で持つ。モデルを交換可能な部品にする、という上位の設計で統合する。

第四に、自動運転とロボティクスの安全の制度の違いである。自動運転は、道路交通の規制と安全ケースを持つ。ロボティクスは、産業用、協働、サービス用の規格が分かれる。系列は、制度ごとの差異を、参照と拡張で吸収する。記録の核を変えない、という上位の設計で統合する。

第五に、意味の対応の正しさを、誰が承認するかである。系列は、対応表と損失の一覧を作るが、移行の正しさを保証しない。承認は、製品の担当と、安全の責任を持つ組織が行う。系列は、承認の印を記録する。この緊張は、系列を記録の層にする、という上位の設計で統合する。

第六に、自動運転をロボティクスの前段と一律に置くことと、参照領域として置くことの緊張である。42は、自動運転を参照領域として読み、一律の時代予測を置かない。本資料の合成fixtureは、その参照領域から項目を借りたものであり、前段の証拠ではない。この緊張は、自動運転を参照領域として置く、という上位の設計で統合する。

## 7. 計画と設計への回収

第一に、四つのスキーマを、計画の暫定成果物に加える。実装の前に、スキーマを固定する。

第二に、検証スクリプトを、評価の再現可能な試験に加える。負例の自己試験を含める。

第三に、自動運転の合成fixtureを、ロボティクスのfixtureの雛形にする。領域を増やすときは、必須の項目だけを変える。

第四に、次の作業は、実車や実ロボットではなく、合成の出来事で、受け渡しと判断の記録が通るかを試すことである。実システムの検証は、別の段階で行う。

## 8. 境界

- 本資料は、暫定決定です。実装、採用、安全認証の約束ではありません。
- 検証は、合成fixtureのみです。実車、実ロボット、実安全制御器は未検証です。
- 安全エンベロープは参照であり、安全認証の証拠ではありません。
- 意味の対応は移行の記録であり、移行の正しさを検証したものではありません。
- 自動運転を、ロボティクスの前に一律に来る時代予測として置きません。参照領域として扱います。
- 定量化、指標、実環境の観測は、本資料の対象外です。
