# 概要資料への反映案

状態: 提案（2026-11-01）。製品群の概要資料「YI Constellation 構想と設計」は別ブランチで公開準備中であり、本資料は変更案です。デッキ自体は編集していません。

本資料は、01から16の分析を、30枚の概要資料へどう反映するかを、スライドごとに整理します。目的は、資料の主張と、分析で分かったことをずらさずに揃えることです。資料の性格を変えるのではなく、現在地と境界の記述を足します。

## 1. 反映の原則

- 資料は、構想と現在地を分ける。分析で分かったことは、構想の水準か、要件の候補か、検証の結果かを明記する。
- 製品の正本を複製しない。資料は案内であり、要求や設計の正本は各製品のリポジトリに置く。
- 卦の頁は、探索の地図として保つ。64の卦を製品計画にしない。残りの卦を、将来の製品や実装計画として扱わない。
- 新しい分析は、分析草稿として参照する。受理済みの要件や、採用済みの設計として書かない。
- 既存の主張のうち、確認できた範囲と、確認していない範囲を、今の資料より明確にする。

## 2. スライドごとの案

### 2.1 スライド1から4 構想と背景

変更は最小にします。

- スライド1の製品一覧は、そのまま保つ。六つの製品名と卦の対応は、本分析でも確認できた。
- スライド2の三つの規模は、そのまま保つ。個人、組織、社会の入れ子の説明は、本分析の四つの系とも整合する。
- スライド3の六つの断絶は、そのまま保つ。本分析の「通塞」は、この断絶の裏側にある滞留として読める。
- スライド4の委任の四段階は、そのまま保つ。四段階は資料独自の整理であり、本分析もその位置づけを変えない。

### 2.2 スライド6 八つの能力と四つの面

任意の変更です。四つの面の下に、媒体の帯を一つ足す案があります。

- 統治面、認知面、実現面、統合面の四つは、そのまま保つ。
- 四つの面の下に、「媒体 ハーネス」と小さく書き、製品ではないことを添える。ハーネスの役割は、意図、文脈、ツール、権限、観測の中継であり、製品の機能ではない。
- 八つの能力の整理は変えない。媒体は、八つの能力のどれかを担うのではなく、能力の間を運ぶ。

この変更は、資料の構成を変えるため、Ownerの判断を待ちます。変更しない場合も、スライド28の注記で媒体に触れます。

### 2.3 スライド8 六つの製品の全体構成

三点を足します。

第一に、TAIの位置づけです。現在の注記は「TAI Pleromaは統合製品」と書いています。これを「TAIは課題をまたぐ輔相製品であり、統合の頂点ではない」と言い直す案です。泰の象伝の「輔相」と、各製品の正本を代行しない非目標に合わせます。用語を変えるかはOwnerの判断です。

第二に、ハーネスの境界です。六つの製品の下に、媒体としてのハーネスを置き、次の一行を添えます。

> ハーネスはセッションと受け渡しの記録を持ち、製品の正本を持たない。

これで、製品群が器官、ハーネスが神経と血管という関係が、資料の上でも見えます。

第三に、SHOの状態です。SHO Composerは製品1/6として提示されていますが、`sho-composer`にはLICENSEと初期コミットしかなく、ADR-0024も提案中です。製品として扱うか、MMIの役割にするか、保留するかは[21-SHOの扱い](21-SHOの扱い.md)で整理中です。資料には、SHOが構想中であることを一行で添える案があります。

### 2.4 スライド9 意味の約束と実行の約束

境界の検査に、ハーネスの行を一つ足します。

- 通す: セッションの状態と、製品の正本が分かれている。
- 拒否: ハーネスが製品の正本を書き換える。

既存の六つの境界（文書→観測、観測→候補、候補→決定、決定→実装、委任→実行、結果→改善）は、そのまま保ちます。

### 2.5 スライド12から20 製品ごとの頁

各頁の本文は変えません。注記に、次の二つを足す案があります。

- その製品の卦の、六爻の局面と、変爻の行き先の要約。たとえばSEIなら、九三が坎へ、九五が升へ移る。
- 相の拡充の候補。たとえばSEIなら、放置と漏洩の検知。

注記は公開資料の一部であり、情報量が増えます。全部の頁に足すか、必要な頁だけにするかは、Ownerの判断を待ちます。

### 2.6 スライド21 TAIの配布

「統合製品」という表現があれば、「輔相製品」に揃えます。配布の構想そのものは変えません。

### 2.7 スライド22と23 連携の例

例の本文は変えません。注記に、ハーネスの役割を一行足す案があります。

- スライド22: 例の各段階は、ハーネスのセッションの中で進む。ハーネスは文脈を保つが、判断の正本を持たない。
- スライド23: 個人の例では、AIや端末を替えても、課題の状態がハーネスから製品へ渡る。社会の例では、参加者の端末と機関の正本を分ける。

### 2.8 スライド26 現在地

ここは、更新の必要が最も大きい頁です。四つを足します。

第一に、要件候補の現在地です。25件の候補を、新規7件、拡張8件、受入検査1件、既存9件に分類し、要求として残るのは15件であることを、一行で示します。分析草稿であり、受理済みではないと添えます。

第二に、参照接続の動作確認です。SCN-001の参照評価と、MMI読み取り専用の参照接続が、2026-11-01に動作したことを示します。実運用の認可や意味の受理ではないと添えます。

第三に、変爻の検査の一部です。仮承認のリンク切れ、リンク先の取り違え、廃止済み判断の復活を、参照評価の失敗として観測できたことを示します。一般の判断記録の到達性は未検査であると添えます。

第四に、製品と卦の対応の点検です。TAI、SEI、TEIは強い対応、SUI、EKIは中程度、SHOは弱い対応であることを、[20-製品と卦の対応レビュー](20-製品と卦の対応レビュー.md)で示しました。SHOの扱いは[21-SHOの扱い](21-SHOの扱い.md)で整理中です。

### 2.9 スライド28 卦の頁

この頁は、本分析の中心的な反映先です。五点を足します。

第一に、巽を媒体として示すこと。64卦の表の巽の位置に、製品ではなく「媒体（ハーネス）」と書きます。巽は製品の卦として空いていますが、製品にする卦ではないことを、注記で説明します。

第二に、変爻の方法です。卦の線を一本変え、之卦の卦辞と象を読む手順を、一行で示します。製品の六爻の変化が、別の製品や影の状態へ移ることを、例で示します。

第三に、候補の絞り込みです。64の卦のうち、新規製品の候補は五つに絞り、そのうち四つを相の拡充へ回し、巽は媒体として外したことを示します。

第四に、但し書きの強化です。「64は製品数の予定ではない」に加えて、「卦が空いていることは、製品の必要性の証拠にならない」と書きます。

第五に、SHOの升の頁の扱いです。SHOを保留する場合、升の頁は製品の頁ではなく、製品の仮説の頁として示します。六爻の読みは、製品の説明ではなく、製品の仮説として読めるようにします。

### 2.10 スライド30 出典

TAIの`docs/yi-constellation/`へのリンクを、分析草稿として足します。とくに、14の既存要求との照合、15のハーネスの卦読み、16の変爻の検査記録を挙げます。

外部の統計と規格の出典は、そのまま保ちます。本分析は、それらの原典を再確認していません。

## 4. 変更しないもの

- スライド1のブランドと製品一覧。
- スライド3の外部統計。原典を再確認していないため、数値も出典も変えない。
- スライド4の委任の四段階。資料独自の整理として保つ。
- スライド24の社会的意義。仮説であるという但し書きを保つ。
- 各製品の頁の本文。要求や設計の正本は、各製品のリポジトリに置く。

## 5. 反映の順序

1. 本資料を、分析の一部としてOwnerがレビューする。
2. 01から16の分析のうち、資料へ反映する範囲を決める。全部を反映する必要はない。
3. 概要資料の更新を、独立した変更として行う。分析のブランチとは分ける。
4. 更新した資料の版と日付を、現在地の頁に記す。分析が受理済みでない間は、分析草稿として参照する。
5. 各製品の要求文書への反映は、G1の採否の後にする。資料の更新が、要求の受理を先取りしないようにする。
