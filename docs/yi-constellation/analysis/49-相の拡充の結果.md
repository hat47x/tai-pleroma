## 2. 共通する形

6件のうち**4件**（TAI・SHO・SEI・TEI）が、同じ形で止まっている。

> **記録はあるが、測りたいことを示す欄が無い。**

| 製品 | 記録はある | 示せないもの |
| --- | --- | --- |
| TAI | SCN-001の17の検査 | 未接続と不受理（検査が接続を扱わない） |
| SHO | 出典報告（範囲・ダイジェスト） | 範囲に行が無いこと |
| SEI | 判断記録（ID・文言・責任） | 参照された時刻・回数 |
| TEI | validate（モデル・診断） | application側の型解決の誤り |

**残る2件は形が違う。** SUIは「畳んだ後も反証が残る」ことを確認でき（既存の道具で測れる）、EKIは「測る設計はあるが、非常時の型が無い」（設計の不足である）。

## 3. この形が意味すること

第一に、**4件の不足は「記録を作り直す」話ではない**。必要なのは欄を足すことであり、既存の記録の構造を変える小さな変更で足りる。これは[48-接続の単位の不足](48-接続の単位の不足.md)で整理した「運ぶ側と受ける側の単位が揃わない」と同じ種類の不足である。

第二に、**4件のうち3件は製品の正本**（SHOの出典報告、SEIの判断記録、TEIのvalidate）にある。TAIが横断担当として欄を足すことはできない。TAIができるのは、欄が足されたときに**それが実際に測れるか**を再実行で確かめることだけである。

第三に、**TAI自身の1件（未接続・不受理）は、TAIが作れる**。SCN-001が接続を扱わないためで、接続を扱うシナリオを足せば例を持てる。ただしそれは新しいシナリオの設計であり、G1の採否（RQ-YI-001と002）に関わる。

## 4. 暫定の判断

**この6件を、要求の採否の材料としてG1へ渡す。** ただし、欄を足すかどうかの判断は各製品のOwnerに残す。TAIは次の二つだけを担う。

1. 6件の結果と共通する形を示す（本文書）
2. 欄が足されたときに、測れるかを再実行で確かめる（各receiptが再実行できる形で残っている）

**今は何も足していない。** 足す先の候補は[48-接続の単位の不足](48-接続の単位の不足.md)に選択肢として並べたが、採否はG1の後である。

## 5. この記録が拠らないもの

- 欄を足した後の意味の正しさ
- 実製品の運用（未実施）
