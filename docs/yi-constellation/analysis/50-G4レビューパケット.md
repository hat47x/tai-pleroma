# G4レビューパケット：坎を製品にするか、相の拡充にするか

状態: 判断用の整理（2026-11-11）。決定ではない。採否を決めるのはOwnerであり、本資料は決定の材料です。

本資料は、[11-新規領域](11-新規領域.md)の判断基準C1〜C5と、[危険の最小単位の棚卸し](../../../evaluations/records/YI-danger-units-2026-11-11.json)、[公開の拒否の観測](../../../evaluations/records/YI-publication-refusal-2026-11-11.json)を突き合わせます。G1の[D4 坎を、どう扱うか](18-G1レビューパケット.md)の判断材料になることを目的とします。

## 1. G4で決めること

1. 坎を、狭い探索候補として残すか、相の拡充に回すか、今は扱わないか。
2. 危険の最小単位5つのうち、どれが既存の記録で観測でき、どれが観測できないか。
3. 坎を残す場合の最小の範囲と非目標。
4. 革・損・觀・節を、相の拡充の優先順位へどう反映するか。

## 2. 危険の最小単位の観測結果

5つの単位が、既存のreceipt 300件にどう現れるかを数えました。

| 単位 | 観測したreceipt | 何で観測したか |
| --- | --- | --- |
| 権限の逸脱 | 13件 | 403・unauthorized・denied |
| 委任の拒否 | 37件 | rejected・refused・409 |
| 権限の期限切れ | 15件 | expired・revoked・stale |
| 検証の失敗 | 32件 | passed=false・untrusted |
| 公開の拒否 | 3件 | gateの`allowed=false`（[観測](../../../evaluations/records/YI-publication-refusal-2026-11-11.json)） |

**5つすべてに観測があります。** ただし件数は偏っています。委任の拒否は37件、公開の拒否は3件です。

### 2.1 この数え方の限界

検索は語彙一致です。receiptの`scope`や注記に「403」と書いてあるだけでも数えるため、**上限**であって、単位そのものの測定ではありません。また、286件のreceiptが`publicationAllowed: false`を宣言していますが、これは**宣言**であって観測ではないので、上の表から外しました。

## 3. 判断基準C1〜C5の当てはめ

[11-新規領域](11-新規領域.md)2.1の5基準に、今回の観測を当てます。

| 基準 | 問い | 今回分かったこと | 評価 |
| --- | --- | --- | --- |
| C1 非目標の確認 | 既存製品の非目標が、危険の検知を明確に拒んでいるか | EKIの脅威モデル・SEIの権限・TEIの監査は、いずれも危険の検知を**中心にしていない**。拒んでもいない | **○（拒んでいない）** |
| C2 正本とライフサイクル | 危険の検知に、独立した正本・版・廃止の単位があるか | **無い**。危険の記録は各製品の監査ログに散らばる | **×** |
| C3 利用者と測定 | 誰が使い、何で価値を測るかが具体的にあるか | 「危険が起きたときに誰が止めるか」は具体的。測り方は**未設計** | **△** |
| C4 中央Hostの不要 | 中央の監視基盤を要しないか | 製品にすると**中央監視に傾く**（11の非目標と衝突） | **△** |
| C5 不在の証拠 | 既存製品の未確認領域が、危険の検知の不在を示しているか | TAIの公開gateは保留、EKIの本番委任は未確認、TEIの実環境接続は未確認。**危険の相は各製品の未確認の底に共通してある** | **◎** |

### 3.1 当てはめから言えること

- **C5が最も強く当てはまります。** 危険の検知は、各製品の未確認領域の底に共通してあります。
- **C2が明確に外れます。** 独立した正本・版・廃止の単位がありません。
- **C4が弱い。** 製品にすると中央監視に傾き、11の非目標と衝突します。

C2とC4が外れるため、**「独立した製品」としては成立しにくい**というのが今回の読みです。一方でC5が強いため、**「何もしない」も根拠が弱い**。

## 4. 選択肢と、それぞれの帰結

### 案A 狭い探索候補として残す

- 何をするか: 危険の最小単位の観測を、既存のreceiptから拾い続ける。新しい製品は作らない。
- 帰結: 今の観測（5単位すべてに1件以上）が既に材料になる。**追加の実装は要らない**。
- 危険: 「探索候補」のまま置かれ、判断が先送りになる。

### 案B 既存製品の相の拡充に回す

- 何をするか: EKIのsecurity event、SEIの権限、TEIの監査を広げる。
- 帰結: C2（正本）とC4（中央Host）の問題を回避できる。危険の記録は各製品の正本に残る。
- 危険: 「危険の検知」が3製品に分かれ、**横断で見る者がいなくなる**。

### 案C 今は扱わない

- 何をするか: 危険の単位の観測だけを残し、判断をG5以降へ送る。
- 帰結: 何も決めない。今の観測は残る。
- 危険: 各製品の未確認領域（C5）が放置される。

### 案D 探索候補として残しつつ、拡充を先に進める（推奨）

- 何をするか: 坎は**製品にしない**。危険の最小単位の観測を保ち（案A）、当面は既存製品の相の拡充（案B）で各製品の未確認領域を埋める。
- 帰結: C2とC4の問題を回避しつつ、C5の強い根拠を放置しない。
- 危険: 横断で見る者がいない状態が続く。ただし、それは**中央監視を作らない**という非目標の帰結であり、欠陥ではない。

**推奨は案Dです。** 理由は、C2とC4が外れる以上、独立した製品としては成立しにくく、かつC5が強い以上、何もしないのも根拠が弱いためです。製品にせず、拡充で埋め、観測を保つ。

## 5. 案Dを採る場合の最小の範囲と非目標

### 5.1 最小の範囲

- 危険の最小単位5つの観測を、既存のreceiptから拾い続ける（既に5件のreceiptがある）。
- 各製品の未確認領域を、相の拡充で埋める（RQ-YI-016 困の検知を先に試す）。
- 坎を製品にするかの再検討は、**C2（独立した正本）が満たされたとき**に行う。

### 5.2 非目標

- 他製品の内部を常時監視する中央の監視基盤を作らない。
- 組織のSIEMやSOCを置き換えない。
- 危険の予知を約束しない。
- 検知のために、製品間の権限を広げない。
- 危険の記録を1か所に集める統合台帳を作らない。
