# H（Harness Reply）の計器はどこまで在るか（2026-11-18）

状態: 実測の記録。Hの計器の評価であり、Owner受理・実装・実配備ではない。

[受渡し条件](54-受渡し条件.md)は、H（Harness Reply）を「計器なし」と整理した。本資料はその判断を、`integrations/harness-adapter/evidence/` の実測記録と突き合わせる。

## 1. 計器は「無い」のではなく「部分的に在る」

[harness-adapterのevidence全10件を読んだ](../../../evaluations/records/YIC-harness-evidence-2026-11-18.json)結果、**4種類のadapterが記録されている**。

```
claude-code, direct-control, dsh-headless, step-cli
```

| adapter | 記録があるか |
| --- | --- |
| `step-cli` | **あり** |
| `claude-code` | **あり** |
| `dsh-headless` | **あり** |
| `direct-control` | **あり**（対照群） |
| `codex-exec` | **なし** |

**§54の「計器なし」は、Hの計器が存在しないという意味ではなく、「`codex-exec`と、4種を並べた比較の計器が無い」という意味だった。** この区別を書いていなかった。

## 2. 4セッションの観測は、4種類のadapterではない

`four-session-observation-2026-11-12.json` は、名前から4種類のadapterを連想させる。実際は**1つのadapter（`dsh-headless`）で4つの割当を走らせた記録**である。

```json
{"allocated": 4, "h2Clean": 2, "h3Loaded": 2}
```

割当は `S1-H2`・`S2-H3`・`S3-H3`・`S4-H2` の4つで、adapterはすべて`dsh-headless`。

**「4セッション」は「4 adapter」ではない。** 読み手が混同しうる箇所なので、明記する。

## 3. 各ファイルが自分で書いている限界

10件すべてが、限界を自分で書いている。

| 書き方 | 件数 |
| --- | --- |
| `notClaimed` 欄 | 3 |
| `notes` 欄（「観測であって合格ではない」等） | 6 |
| 該当なし（配列形式の記録） | 1 |

**6件は`notClaimed`という名前の欄を持たない。** 限界を書いていないのではなく、別の欄に書いている。名前だけで判定すると「限界を書いていない」と誤る。

## 5. §54の記述をどう直すか

§54のH行は「計器なし」と書いた。これは**「Hの成立条件を測る計器が無い」**という意味では正しい。しかし**「Harness adapterが何も記録していない」**という意味ではない。

| 誤読しうる読み | 正しい読み |
| --- | --- |
| Harness adapterは未実装 | **4種が実装・記録済み**、`codex-exec`のみ未記録 |
| 何も測っていない | **割当・Skill配置・回答有無は測っている** |
| Hは成立している | **Hの成立条件（Reply終端・Session同定）は測っていない** |

## 5.1 `codex-exec`は「実装が無い」のではなく「実行記録が無い」

§1で`codex-exec`を「記録なし」と書いた。**記録が無いことと、実装が無いことは違う。** adapterは存在し、testsも存在する（[実行](../../../evaluations/records/YIC-codex-adapter-2026-11-18.json)）。

```text
passed: 7, skipped: 0, failed: 0
codex CLI on this host: 無い
evidence files mentioning codex: 0
```

| test | 何を確かめるか |
| --- | --- |
| `TestCodexExecRunIsBoundedAndNeverProductAccepted` | 実行はboundされ、製品の受理を作らない |
| `TestCodexExecRejectsUnboundCapabilitiesBeforeLaunch` | 束縛されていない能力は起動前に拒否 |
| `TestCodexExecIncompleteResultsDoNotPass` | 不完全な結果は合格にしない |
| `TestCodexExecRefusesOversizedOutputAndUnknownRoot` | 過大出力と未知のrootを拒否 |
| `TestCodexExecProbeDoesNotAssumeInstallation` | **未インストールを前提にしない** |
| `TestCodexExecExactVersionPin` | 版の固定 |
| `TestCodexExecUnknownControlEventRequiresRequalification` | 未知の制御イベントは再資格確認を要求 |

### 5.1.1 testsが確かめていないこと

**このホストに`codex` CLIは無い。** testsは`scripted`なrunnerを差し替えており、**外部プロセスを起動しない**。したがって確かめているのは解析と拒否経路であり、実CLIの起動・認証・sandbox・Tool権限ではない。

**`TestCodexExecProbeDoesNotAssumeInstallation`という名前は重要である。** 未インストールの状態を「異常」ではなく「前提されていない」として扱う設計であり、§1の「記録なし」を「未対応」と読むのを防ぐ。

### 5.1.2 それでもHの成立は測れていない

**7件のPASSは、Hの成立条件（Reply終端・Session同定）を測ったものではない。** adapterが壊れていないことの確認であって、Hが成立していることの証拠ではない。
