# 願いの要件

状態: 自由な提案（2026-11-01）。願いの形をした要件の候補であり、構造の要求でも、採用の約束でもありません。

本資料は、[22-価値の共鳴](22-価値の共鳴.md)の願いの要件を、[31-価値の語彙](31-価値の語彙.md)の言葉で書き直し、質的な受入の見方と、約束しないことを添えます。構造の要求（RQ-YI）を置き換えません。願いの要件は、要求の言葉を、利用者の側から書くための層です。

## 1. なぜ願いの要件か

構造の要求は、何を満たすかを決めます。しかし、構造の要求だけでは、利用者が「これは自分のためのものだ」と感じるかは分かりません。願いの要件は、利用者の言葉から始めます。

- 私は、〜したい。
- その願いが要る場面は、これだ。
- その願いが届いたとき、その人は、自分の言葉でこう言う。
- ただし、これは約束しない。

この四つを一組にします。質的な受入は、点数ではなく、その人の言葉です。

## 2. 七つの製品の願いの要件

### 2.1 TAI 泰

**WISH-01。** 私は、自分の課題がどこで止まっているかを、五分で説明できる。

- 相手。実務者。
- 場面。会議で決まったのに、次の部門へ渡っていない。
- 価値語。交、渡る。
- 届いたときの言葉。「どこで止まったか、これで説明できる。」
- 約束しないこと。全部の流れが見えることは約束しない。止まった場所が見えるだけ。

**WISH-02。** 私たちの組織は、中央の台帳を買わずに、部門をまたぐ流れを見られる。

- 相手。経営。
- 場面。部門ごとの記録はあるが、全体の流れが見えない。
- 価値語。交、輔相。
- 届いたときの言葉。「中央に台帳を置かずに、流れが見える。」
- 約束しないこと。全部の部門が同じやり方になることは約束しない。

**WISH-03。** 社会は、決定が誰に届かなかったかを、人を責めずに記録できる。

- 相手。公共、監査。
- 場面。決定はされたが、届かなかった人がいる。
- 価値語。交、渡る。
- 届いたときの言葉。「届かなかった人を、責めずに記録できる。」
- 約束しないこと。届かなかった人が救われることは約束しない。記録が残るだけ。

## 4. 願いの要件の書き方

第一に、「私は」から始める。製品名から始めない。

第二に、一つの願いに、一つの場面を付ける。場面のない願いは、抽象になる。

第三に、届いたときの言葉を、その人の言葉で書く。「便利になる」ではなく、「どこで止まったか、これで説明できる」。

第四に、約束しないことを、必ず書く。願いは、約束ではない。

第五に、質的な受入は、点数にしない。その人が自分の言葉で語ったら、届いたと見る。語らなければ、届いていないと見る。

## 5. 構造の要求との関係

- RQ-YIは、何を満たすかを決める構造の要求です。願いの要件は、その要求を、利用者の側から書いた層です。
- 願いの要件は、構造の要求を置き換えません。構造の要求がなければ、願いは絵に描いた餅になります。
- 構造の要求は、願いの要件を置き換えません。構造だけでは、利用者が自分のためのものと感じるか分かりません。
- G1では、願いの要件を、価値のテストに使えます。候補を採用するとき、その候補がどの願いに響くかを、一行で添える。
- 願いの要件は、採用の約束ではありません。G1の判断を、先取りしません。

## 6. CSWへの還元について

本資料は、要件の書き方であり、CSWへ戻す新しい書き方の技法は見つけていません。「私は」から始める形は、要求の形式であり、文章の技法ではありません。場面を先に置く手つきは、[25-価値の味わい](25-価値の味わい.md)で戻しています。

## 7. 境界

- 本資料は、願いの形をした要件の候補です。採用、実装、効果を約束しません。
- 願いの人物は、分析者が構成したものです。実在の利用者ではありません。
- 届いたときの言葉は、設計者の案です。利用者が同じ言葉を言うとは主張しません。
- 構造の要求（RQ-YI）を置き換えません。G1の判断を先取りしません。
- 定量化、指標、検証は、本資料の対象外です。
